# ADR-0002: 采用内存注入获取游戏状态

## Status

Accepted

## Context

RA2/YR 引擎发布于 2000 年，不提供任何 AI/Bot 开发的原生 API。外部程序获取游戏状态的可行方案有三种：

1. **屏幕捕获 + 计算机视觉** — 截屏、OCR、目标检测
2. **内存注入** — DLL 注入游戏进程，直接读取内部对象
3. **网络协议解析** — 抓取对战平台的联机协议数据

对比关键维度：

| 维度 | 屏幕捕获 | 内存注入 | 网络协议 |
|------|----------|----------|----------|
| 延迟 | 50-100ms | < 5ms | 取决于平台 |
| 状态完整性 | 仅视野内像素 | 全量精确数据 | 部分聚合数据 |
| 计算开销 | 高（CNN 推理） | 极低 | 低 |
| 稳定性 | 受分辨率/UI 影响 | 稳定（版本锁定） | 平台依赖 |
| 开发成本 | 高（需训练 CV 模型） | 中（依赖现成库） | 极高（需逆向协议） |

AlphaStar 在 StarCraft II 上的做法是通过暴雪提供的 API 直接读取结构化状态。本项目无官方 API，但 `ra2yrcpp` 提供了类似能力：通过 Syringe 注入 DLL、YRpp 访问游戏对象、Protocol Buffers 序列化状态。

## Decision

采用 **内存注入** 方案。技术实现：

- `ra2yrcpp` (C++ DLL) 注入 `gamemd.exe`，Hook 游戏主循环
- 利用 YRpp 访问 `TechnoClass`、`HouseClass`、`MapClass` 等游戏内部对象
- 状态序列化为 Protocol Buffers，通过 Socket 发送
- `pyra2yr` (Python) 客户端解码并暴露异步 API

## Consequences

**收益：**
- 训练效率：< 5ms 延迟 + 结构化数据，无需 CV 预处理
- 观测完整性：可获取战争迷雾下的完整状态（便于 reward shaping 与调试）
- 数据精确性：血量、冷却、建造队列等隐藏信息均可读取
- 同步精度：通过游戏主循环 Hook 实现 lock-step 训练

**代价与约束：**
- 强依赖 `ra2yrcpp` 与目标游戏二进制的版本匹配（见 ADR-0004）
- `ra2yrcpp`/`pyra2yr` 为小规模开源项目，需自行承担维护风险
- 与屏幕捕获方案相比，部署到不同游戏版本的迁移成本更高
